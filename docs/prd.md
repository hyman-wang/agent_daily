# Agent Journal 产品需求文档（PRD）

## 1. 项目信息

- **Language**：中文
- **Project Name**：`agent_journal`
- **Programming Language**：建议 Python 3.10+ 标准库实现采集、匹配与报告生成；报告使用原生 HTML/CSS/JavaScript。Windows Hook 命令经 Git Bash 执行，不引入本地 Web 服务或前端构建依赖。
- **开源方式**：GitHub 开源、MIT License、中文 README、贡献指南、自动化测试、手工测试清单与 GitHub Actions；用户无需部署。
- **原始需求复述**：为本机安装的各类 Agent 记录每次用户提问及对应回答，实时生成可双击打开的 HTML 日报、周报和总索引；通过全局 Skill 提供生成、打开、重建和整理入口，但采集不能依赖模型主动调用 Skill。数据仅存本机，安装与卸载不得破坏已有配置。

## 2. 产品定义

### 2.1 产品目标

1. **确定性留痕**：支持的 Agent 每次提交问题时先记录 `pending`，回答结束后匹配并更新同一逻辑记录，不依赖二次读取对话或模型记忆。
2. **离线可读**：提问与回答两个阶段的摘要和原文均进入日报/周报，报告可通过 `file://` 双击查看，无网络、账号或本地 HTTP 服务依赖。
3. **安全可维护**：本机存储、配置可合并、操作幂等、异常不阻断提问，并可备份导出、彻底卸载和恢复项目相关原配置。

### 2.2 非目标

- 不做云端同步、在线多人协作、账号体系、远程管理或遥测。
- 不宣称首版实时覆盖所有 Agent；未核实 Hook 能力的宿主只能标为补采或手动导入。
- 不用 AI 摘要替代原始记录；AI 润色不是采集、匹配或报告生成成功的必要条件。
- 不做通用聊天客户端、Agent 执行器、任务调度平台或网页 Agent。
- 不保证从已损坏、已删除或无读取权限的历史 transcript 中恢复回答。
- 首版不提供复杂的团队统计分析、语义搜索和可视化 BI。

## 3. 目标用户与核心用户故事

**目标用户**：在本机使用多个编程/办公 Agent，需要复盘工作、整理日报周报、保留决策上下文的开发者、产品经理和知识工作者。

1. 作为多 Agent 用户，我希望每次提问后自动留下 `pending` 记录，以便即使回答中断也不会丢失问题。
2. 作为多 Agent 用户，我希望回答结束后自动关联到原问题并标记 `complete`，以便日报同时呈现“问了什么”和“得到什么结果”。
3. 作为复盘用户，我希望双击 HTML 就能离线查看日报/周报并展开问答原文，以便无需启动服务即可回顾。
4. 作为并行工作者，我希望不同 Agent、session 和连续多轮问答不会串线或重复，以便记录可信。
5. 作为注重隐私的用户，我希望明确知道数据位置、权限和导出方式，以便控制敏感提问与回答。
6. 作为已有 Hook 用户，我希望安装不覆盖现有配置、卸载只移除本项目内容，以便安全试用。

## 4. 核心边界与记录模型

### 4.1 双阶段采集是 P0 主链路

- **问题阶段**：`UserPromptSubmit` 收到每次用户 prompt 后立即追加本地 JSONL，创建稳定 `record_id`，状态为 `pending`，生成确定性问题摘要，并同步更新受影响的日报、周报和 `index.html`。
- **回答阶段**：`Stop` 触发后，利用输入中的 `session_id`、`transcript_path` 及可用时的 `generation_id` 读取 transcript，定位本轮回答并更新同一 `record_id`；状态按结果为 `complete`、`partial` 或 `failed`，生成确定性结果摘要并同步重建报告。
- **不得假定** `Stop` 输入本身含完整 `answer` 字段。transcript 的具体格式、轮转时机和各宿主 Stop/SessionEnd 输入由架构师依据官方文档与实测核实。
- JSONL 可采用事件追加方式表达状态变更，但报告中同一轮问答必须只有一个逻辑条目；回答重试可保留修订事件，不得重复显示问题。

### 4.2 最少数据字段

每条逻辑记录至少包含：

- `schema_version`、`record_id`、事件去重标识、适配器版本；
- `agent`、`session_id`、可选 `generation_id`、项目标识及采集时的 `cwd`；
- 问题原文、回答原文（若取得）、问题摘要、结果摘要；
- `asked_at`、可选 `completed_at`、可选 `duration_ms`、`status`；
- 可选错误码/错误说明、回答修订号、更新时间。

时间使用含时区的 ISO 8601 格式，报告按本地日期归组。原文永不因摘要或润色被覆盖；项目展示名与本地完整路径应区分。

### 4.3 状态定义

- `pending`：问题已落盘，尚未取得可确认的本轮回答；活跃会话中不得因暂时未匹配而直接判失败。
- `complete`：已取得并匹配本轮完整回答。
- `partial`：回答中断、崩溃或会话结束时仅取得部分内容；保留已取得的回答原文。
- `failed`：补处理后仍无回答可取得，或宿主明确返回失败；保留问题及失败原因。
- 无法确认匹配关系时不得猜测关联、伪造回答或静默丢弃，应保留诊断信息并留待补处理。

## 5. 需求池

### P0：必须有

1. **实时问题采集**：为 WorkBuddy/CodeBuddy 与 Claude Code 接入用户级 `UserPromptSubmit` command Hook；每次提交均写 JSONL，正常与异常路径均以退出码 0 返回，不阻止、不修改用户提问。
2. **回答采集与匹配**：为上述 P0 宿主接入 `Stop`；基于 session、generation（可用时）及 transcript 轮次定位回答，不得用全局“最后一条 pending”作为通用匹配规则。
3. **中断补处理**：支持 SessionEnd（宿主能力核实后）及下次运行/手动重建时扫描未完结记录；transcript 暂不可读时允许有界重试，最终保留 `partial`/`failed`，不得无限等待。
4. **幂等与并发安全**：重复问题事件、重复 Stop、同一 generation 重试不产生重复逻辑条目；并行会话写入不得损坏 JSONL 或互相覆盖。采用原子写入/必要锁机制，崩溃后不得留下无法解析的半行。
5. **确定性摘要**：本地规则清理空白与 Hook 元数据，生成有长度上限的问题/结果摘要；无模型、无网络也能完成。原文完整保留。
6. **静态报告**：每次有效状态变更后同步更新当天日报、所在周周报和总索引；报告同时展示整理后的问题与结果，并用 `<details>` 或等效方式展开原文，明确展示状态、Agent、项目和时间。
7. **完全离线**：HTML 内嵌数据或生成静态内容；禁止依赖 CDN、远程字体、远程脚本、`fetch` 本地 JSON、HTTP 服务。断网后双击可用。
8. **全局 Skill 入口**：提供含 `SKILL.md`、脚本及必要模板的全局 Skill，支持自然语言或命令“生成/打开今天日报”“生成/打开本周周报”“重新构建报告”“导出备份”。Skill 只调用本地工具，不承担逐条采集职责。
9. **直接入口**：用户不经过 Skill 也可双击 `index.html`、日报或周报；提供本地 CLI 作为跨宿主一致入口。
10. **本机数据与配置**：默认存于当前用户目录下的 `.agent-journal/`（数据、报告、日志、备份分子目录），支持配置文件/环境变量修改；不得假定 WorkBuddy 数据根目录，也不得盲写 `D:\WorkBuddyData` 或默认路径。
11. **备份导出**：导出原始 JSONL、配置说明与报告到用户指定目录/压缩包；导出前披露其中含问答原文。
12. **安全安装**：检测宿主、实际用户配置路径、Git Bash/Python 与现有 Hook；合并而非覆盖 settings/hooks，安装前备份，重复安装幂等。Claude Code 可核实后采用插件 `hooks/hooks.json` 或用户 settings。
13. **安全卸载**：仅移除本项目添加的 Hook、Skill 和命令；保留其他配置及用户数据，恢复本项目接管前的相关配置项。卸载脚本自身不删除备份，是否删除数据由用户另行明确选择。
14. **可诊断性**：本地记录采集、匹配和报告错误，提供重建/状态检查命令；任何 Hook 错误不得阻断提问，也不得静默吞掉而无日志。
15. **可扩展适配器**：Agent 探测、事件标准化、transcript 解析、匹配与报告解耦，使后续宿主只需新增适配器，不改核心记录模型。
16. **开源交付**：中文 README 写明支持矩阵、存储位置、敏感信息风险、安装/卸载、双击查看、备份和故障排查；补齐 MIT、CONTRIBUTING、自动化测试、MANUAL_TESTING 与 GitHub Actions，无部署步骤。
17. **旧初稿边界**：根目录浏览器扩展相关文件视为废弃初稿，不属于新方案运行链路；实现阶段由主理人决定清理或归档，任何删除不得由产品经理执行。

### P1：应该有

1. 为 Codex CLI、Gemini CLI、Cursor、Windsurf 等逐项核实 Hook/transcript 能力；具备能力再接实时问答采集，否则提供明确标注的补采或手动导入。
2. 通用 JSON/JSONL 导入格式与导入器，供其他本地 Agent 适配；导入内容必须带来源且遵循相同去重规则。
3. Skill 事后 AI 整理/润色摘要；结果写回摘要字段并保留原文及未润色版本，失败不影响已有报告。
4. 报告按 Agent、项目、状态筛选与本地关键词搜索；所有功能仍离线可用。
5. 敏感项目/目录排除规则、可选保留期限和备份加密说明；默认不排除、不自动删除。
6. macOS/Linux 安装器的完整验证；核心采集与报告代码尽量保持跨平台。

### P2：可以有

1. 月度报告、标签、收藏与自定义摘要模板。
2. 回答修订对比、记录健康度趋势、工作量统计图表。
3. 用户主动选择的加密导出或外部备份目标集成。

## 7. 简单流程说明

### 7.1 安装

检测实际环境与配置路径 → 展示数据位置和支持能力 → 备份相关配置 → 合并本项目 Hook/全局 Skill → 初始化数据目录与空索引 → 执行一次自检。重复执行不得增加重复 Hook。

### 7.2 每次问答

1. 用户提交问题，`UserPromptSubmit` 标准化事件并写入 `pending`；先保证 JSONL 持久化，再同步刷新报告，最后始终以 0 退出。
2. Agent 回答结束，`Stop` 从输入获取 session、transcript 路径及可用 generation；读取 transcript，不依赖想象中的 `answer` 字段。
3. 匹配原 `record_id`，追加完成/部分完成/失败事件，生成结果摘要并刷新日报、周报、索引；失败写日志但仍以 0 退出。
4. SessionEnd、下次运行或手动重建继续处理未完结记录；报告是 JSONL 的可重建视图，JSONL 是事实来源。

### 7.3 查看与整理

用户通过全局 Skill/CLI 生成或打开报告，或直接双击 HTML；可选 AI 润色只更新摘要，不回写原文，也不影响采集。

## 8. UI 设计草图

- **index.html**：本机报告导航，列出最近日报、周报、数据位置说明和重建时间；无服务端页面。
- **日报/周报**：按日期与项目/Agent 分组的时间线；每条依次显示问题摘要、结果摘要、状态、Agent、项目、提问/完成时间与耗时。
- **原文区**：问题原文和回答原文分别可展开；长文本保留换行并转义 HTML，避免脚本注入。
- **异常可见性**：`pending`、`partial`、`failed` 有文字状态，不仅用颜色区分；无回答时显示明确原因或“等待补处理”，不得显示虚构结果。
- **离线交互**：展开、基础导航使用原生 HTML/CSS/内联 JavaScript；JavaScript 禁用时核心问答内容仍可读。

## 9. 隐私与异常策略

1. 默认仅在当前用户本机保存问答原文、摘要、transcript 定位信息和报告，不上传、不遥测；AI 润色必须由用户主动触发并另行披露其数据路径。
2. README、安装提示和报告页脚披露默认/实际数据目录、配置方式、明文敏感信息风险、备份与卸载行为。目录权限在操作系统支持时限制为当前用户。
3. HTML 对问答原文与项目名进行转义；导出文件包含敏感原文，需明确提示。
4. Hook 采用“采集失败不阻断宿主”的原则：所有可预期异常捕获、记录、退出 0；不得输出会污染宿主协议的多余 stdout。
5. JSONL 写入与报告更新分离：报告失败不回滚已落盘事实，可在下次事件或重建时恢复；写入失败则记录错误并在下一次状态检查中可见。
6. transcript 缺失、权限不足、格式变化或回答为空时，按证据保留 `pending`/`partial`/`failed`，不猜测、不伪造；格式升级通过 `schema_version` 和适配器版本兼容。
7. 报告重建必须可从 JSONL 重复执行，不能依赖网络或原始 Agent 仍在运行；补采 transcript 时才需要对应历史文件仍存在。

## 10. 验收标准

以下 P0 用例均须进入手工测试清单；可自动化部分进入 CI。WorkBuddy/CodeBuddy、Claude Code 分别在实际支持环境执行宿主集成测试。

### 10.1 采集、回答与连续多轮

1. **双阶段实时性**：提交问题后，无需二次读取会话，JSONL 立即新增一条 `pending`，报告展示问题摘要与原文；Stop 后同一 `record_id` 更新为 `complete`，报告展示结果摘要与回答原文，不产生第二条问题。
2. **字段完整**：完整问答包含第 4.2 节必需字段；耗时由提问与完成时间计算，缺失回答时不伪造完成时间或耗时。
3. **连续多次提问**：连续完成至少 20 轮问答，每轮问题与回答一一对应，日报和周报均包含 20 条；无丢失、串线、重复，顺序与时间一致。
4. **连续相同问题**：用户有意提交两次相同文本但属于不同事件/轮次时保留两条；完全相同事件的重复投递只保留一个逻辑条目。
5. **报告失败隔离**：模拟报告目录不可写，问题或回答事件仍安全落盘，Hook 退出 0；恢复权限并重建后报告完整。

### 10.2 并行、重试与重入

6. **并行会话**：同一 Agent 开启至少两个 session，按 A1、B1、A2、B2 交错提问并以不同顺序结束回答；四条记录均匹配正确，不跨 session，不覆盖 JSONL。
7. **跨 Agent 并行**：两个 P0 Agent 同时运行时，匹配键包含 Agent/session，项目与回答不串线。
8. **同一 generation 重试**：同一问题轮次重试或重复投递不新增重复问题；若回答内容变化，保留回答修订事件且报告只显示一个逻辑条目及明确的最新回答，旧原文仍可追溯。
9. **Stop 重入**：同一 Stop 事件重复执行至少 3 次，逻辑记录数不变、摘要与状态不重复、耗时保持稳定，报告不重复。
10. **错误匹配防护**：模拟无法定位 transcript 轮次或 generation 缺失的模糊事件，不得把回答附到全局最新问题；记录可诊断原因并等待补处理。

### 10.3 中断与补处理

11. **回答中断**：构造仅有部分回答的 transcript，经 SessionEnd 或下次补处理后状态为 `partial`，部分原文可见。
12. **崩溃/无回答**：只有 `pending` 而无回答时，会话结束或后续补处理后标为 `failed` 或带明确原因的待补处理状态，问题不丢失，报告不伪造答案。
13. **延迟 transcript**：Stop 时文件暂不可读，按有界策略重试或留待重建；Hook 不无限等待、不阻断宿主，文件恢复后可更新为 `complete`。
14. **重复补处理**：对同一未完结记录重复运行 SessionEnd/重建，状态转换幂等，不重复记录或覆盖更完整回答。

### 10.4 离线报告与重建

15. **双击离线打开**：断网并禁止本地 HTTP 服务，直接双击 `index.html`、日报和周报，问题/结果摘要、状态及问答原文均可见；无 CDN、远程资源或对本地 JSON 的 `fetch` 依赖。
16. **多日期归组**：跨天、跨周事件进入正确日报/周报，索引链接有效；时区和周起始日在 README 固定说明。
17. **确定性重建**：删除可再生成的 HTML 后从 JSONL 重建，内容、状态、回答修订与原文一致；全程无模型、无网络。
18. **注入安全**：问答原文含 HTML/脚本字符时被转义，展开原文不会执行其中脚本。

### 10.5 安装、配置与卸载

19. **已有 Hook 保留**：预置可观测的其他 Hook 与自定义 settings，安装后其字段、顺序语义及执行能力保持；本项目 Hook 追加且不重复。
20. **幂等安装**：连续安装两次，配置无重复项，数据不重复，备份策略可追溯，第二次安装不覆盖第一次之后的新增用户配置。
21. **自定义数据根目录**：将数据目录配置到非默认位置，并模拟 WorkBuddy 数据根为 `D:\WorkBuddyData`；采集和报告只使用实际配置，不盲写默认宿主路径。
22. **卸载恢复**：卸载后仅本项目 Hook/Skill/命令被移除，预置及安装后新增的其他 Hook 保留，本项目相关原配置从备份正确恢复；问答数据默认保留。
23. **备份导出**：在无网络环境导出并在另一目录校验 JSONL、配置说明和报告完整；导出提示包含敏感原文风险。
24. **异常不阻断**：模拟无权限、损坏 transcript、非法输入、报告生成异常，Hook 均退出 0、不妨碍提问，并留下本地诊断日志。

## 11. 待确认事项（不阻塞既定方向）

1. 各 P0 宿主 Stop、SessionEnd 的实际 stdin 字段、transcript schema、写盘时序及 generation 稳定性，由架构师通过官方文档和实测确认。
2. Windows 以外平台及各宿主全局 Skill/插件的准确安装目录，以官方文档和环境检测为准。
3. 周起始日建议固定为周一，摘要默认长度、报告保留周期与单文件大小阈值可在实现配置中确定。
4. 同一 generation 的回答修订在 UI 中默认展示最新版本，是否提供版本切换属于 P2。
5. 旧浏览器扩展文件的归档位置和删除时机由主理人决定，不影响新 PRD 执行。

以上待确认项只影响适配器细节和默认参数，不改变“全局 Skill + Hook 双阶段采集 + 本地 JSONL + 离线静态 HTML”的既定方向。
